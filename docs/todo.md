## 段階1(小節検出)

- [ ] **写真の質判定を実際に止める**。読み取れない写真は写真全体をエラーにして撮り直しを促す。
  - 現状は `detect_measures.py` が `errors` に貯めて `ERROR:` と印字するだけで、`measures.json` は常に出る(非致命)。
  - 閾値: `MAX_CURVE=3.0` / `MIN_COVERAGE=0.3` / `MIN_WIDTH_RATIO=0.8`。spec.md 段階1・段階5 の方針どおりに配線する。
- [x] ~~鉛筆除去の閾値(`PENCIL_DARKNESS=180`)が実態と合うか検証~~ → **妥当**。9段目実測で印刷 darkness≈205〜227、鉛筆≈157〜166。180はちょうど谷間。`spike/debug_barlines.py` で確認。
- [ ] **符尾(stem)判定の誤検知を減らす**(`barlines.py` の `_looks_like_stem`)。音符が密集した段では、全高に届く濃い小節線でも端の左右にインクがあり `stem=1` で落ちる。9段目の見落とし(枠55が2小節)の真因。
  - 試した: 「線の全高で、すぐ左右に接するインクの割合」で孤立線=小節線を拾う案。→ **ダメだった**。符頭は全高の約1/4しか占めず、小節線と符尾の差が小さい。閾値を 0.05〜0.18 掃引しても、どの値でも全段で正解にならず(9段目を4にすると7段目が暴走、など)、旧判定(9/10)に勝てず戻した。
  - 次に試すなら: 単純な隣接割合でなく、符頭そのものを検出する/段ごとに閾値を適応させる 等のより賢い指標が要る。当面は段階2のAIが拾うので優先度は低い。
