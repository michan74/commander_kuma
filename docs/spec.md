## 経緯・課題

* 楽器の練習時に、変拍子やGPなど練習がしにくい
* メトロノームを鳴らすだけだと楽譜に対してどこまで進んでいるかわからなくなる

## 解決方法

* 楽譜の写真をとって、読み込ませると、指揮をふってくれる
  * メトロノームの音として表現するモード
  * 振る動作を見るモード
* 楽譜のどの小節かを、メトロノームの音とともにハイライトで表す

## できること

* YouTube動画のURLと楽譜画像を渡す
* YouTube動画の再生に合わせて、指揮が振られる、楽譜の現在の小節がハイライトされる

## スコープ

* 対象
  * パート譜
* 対象外(最初は)
  * リピート・D.S.などの演奏順の展開

  * 小節内での位置表示(拍ごとにバーを動かす表現)

### 全体の流れ

1. 楽譜画像 → 小節候補(位置のみ)
2. 小節候補 + 楽譜画像 → AIが検証・補正 → 小節(位置のみ)
3. 小節 + 楽譜画像 → AIが読解 → 楽譜JSON
4. YouTube URL → 音声 → 拍候補の時刻
5. 楽譜JSON + 音声 + 拍候補 → 拍タイムライン
6. 拍タイムラインに合わせて、フロントが指揮と小節のハイライトをする

### 楽譜画像処理

* 「小節の位置を求める」と「楽譜の内容を読む」を別の段階に分ける
  * 位置は画像処理、内容の読解はAIと、得意分野で分担する
  * 失敗したときに、どの段階が悪いか切り分けられる

#### 段階1: 小節検出(画像処理のみ)

* 入力: 楽譜の写真
* 出力: 段ごとの画像と、読み順に並べた小節候補の配列
  * この時点では小節の意味は持たない
* 段階1は、見落としより誤検出を許容する
  * 段階2のAI補正は削除・結合しかできず、見落とした小節線を追加できないため
* 読み取れない写真は、写真全体をエラーにする(「撮り直してください」)
  * 一部の段だけハイライトされても練習に使えないため

```
[
  { "index": 0, "bbox": { "page": 1, "x": 120, "y": 340, "w": 410, "h": 90 } },
  { "index": 1, "bbox": { "page": 1, "x": 530, "y": 340, "w": 380, "h": 90 } }
]
```

##### 用語

* 段: 五線1本分の行。1ページに複数ある
* すき間: 五線の線と線の間の距離(px)。楽譜の記号の大きさの基準になる
* 短冊: 五線を探すために、画像を縦に細く切った列

##### 1. 2値化

* 入力: 楽譜の写真
* 処理
  * グレースケールにする
  * 適応的二値化をする
    * 蛍光ペンの色と影が消える
* 出力: 白黒画像

##### 2. 物差しの測定

* 入力: 白黒画像
* 処理
  * 画像を縦に1列ずつなぞり、黒と白が続く長さを数える
  * 一番多い黒の長さを線の太さ、一番多い白の長さをすき間とする
    * 余白や文字は回数が少ないので、結果に影響しない
* 出力: 線の太さ、すき間(px)
* エラー: すき間が小さすぎる(引きすぎ)
* 以降のサイズは、すべてすき間の何倍かで決める
  * 写真の解像度・撮影距離に依らなくするため

##### 3. 段の検出

* 入力: 白黒画像、すき間
* 処理
  * 画像を短冊に切る。幅はすき間から決める
  * 短冊ごとに横方向の黒の量を数え、等間隔に並ぶ5本の線の組を、すべて候補にする
    * 加線を含んで1〜2本ずれた組も候補に入る
  * 短冊ごとの候補を左から右へつなぎ、段にする
    * 直近の点から予測した位置に一番近い候補を選ぶ
    * 予測とのずれが、すき間の半分を超える候補はつながない(ずれた組を拾わないため)
  * 長い段と重なって並走する短い段は捨てる(ずれた組から生まれた段)
  * 高さがすき間4つ分から外れる段は捨てる(加線・連桁による偽の五線)
* 出力: 段の配列。段ごとに、x ごとの五線の上端・下端
* エラー: 5本等間隔の線が見つからない(寄りすぎ、楽譜でない)

1. ✅️ 短冊に切って五線を探す
  - 👍️ 細い短冊の中では、傾いた線もほぼ水平になる
  - 👍️ 紙の曲がりも追える
  - 👍️ 場所ごとの五線の位置がわかるので、写真の質を判定できる
  - 🥕 短冊の幅を決める必要がある

2. 🗑️ 画像全体を少しずつ回し、横方向の黒の量が一番くっきりする角度で回す
  - 👍️ 短冊の幅を決めなくてよい
  - 🥕 わかるのは全体の角度1つだけ。紙の曲がりはわからない
  - 🥕 写真が読めない状態でも角度を返してしまい、失敗に気づけない

-> **写真の質の判定にも使えるため、短冊にした。**


##### 4. 段の切り出しと水平化

* 入力: 楽譜の写真、白黒画像、段の配列
* 処理
  * 段ごとに、五線の位置に直線を当てはめて傾きを出す
  * 段ごとに切り出して、水平に回す
* 出力: 段ごとの画像(カラー、白黒)

1. ✅️ 段ごとに回す
  - 👍️ 斜めから撮った台形のゆがみで、段ごとに傾きが違っても水平にできる
  - 👍️ AIには段ごとに渡すので、段の外の傾きは関係ない
  - 🥕 台形のゆがみが強いと、段を水平にしても小節線が斜めに残る

2. 🗑️ 画像全体を、段ごとの傾きの中央値で回す
  - 👍️ 処理が1回で済む
  - 🥕 段ごとに傾きが残る。試した写真では ±2° 程度残った

-> **AIに段ごとに渡すため、段ごとに回す。**


##### 5. 写真の質の判定

* 入力: 段の配列(4で回した後)
* 処理
  * 曲がり: 五線の位置が、当てはめた直線からどれだけずれているか
  * 途切れ: 段のうち、五線が見つかった短冊の割合
* 出力: なし(判定のみ)
* エラー
  * 直線からのずれが大きい(紙の曲がりすぎ)
  * 五線が見つかった短冊の割合が低い(影・しわ)
* TODO: エラーにする閾値(すき間の何倍か、何割か)
  * 読める写真(dance.jpeg)の実測: 曲がり 0.10〜2.16倍、検出率 43〜78%
  * 読めない写真の例を集めてから決める

##### 6. 小節線の検出

* 入力: 段ごとの画像(カラー、白黒)、すき間
* 処理
  * 縦に長い線だけを取り出す
  * 次をすべて満たす線を小節線とする
    * 五線の上端から下端まで、ちょうど届いている
      * 五線の外にはみ出す符尾・鉛筆の線を除く
    * 線の端に符頭が付いていない
      * 符頭は線の片端の片側にだけ付く
      * 拍子記号・休符は、線の両端で同じ側に並ぶので区別できる
    * 元の写真でのインクが濃い
      * 鉛筆の書き込みを除く
* 出力: 段ごとの小節線の x の配列

##### 7. 小節候補の作成

* 入力: 段の配列、小節線の配列
* 処理
  * 段を小節線で区切る
  * 上の段から順、段の中では左から順に `index` を振る
  * 段の最後の小節線より後ろの短い区間は、小節にしない
    * 次の段の予告拍子のため
* 出力: 小節候補の配列

##### 小節検出の方法

1. ✅️ OpenCVで自前に検出する
  - 👍️ 写真全体(3024x4032)で約2秒
  - 👍️ 試した写真では、1〜9段目の小節数が9段中6段で一致(見落とし2本、誤検出2本)
  - 🥕 閾値の調整が必要

2. 🗑️ OMRライブラリ(oemer)を使う
  - 🥕 拍子記号を読めない。5/8 の数字を音符と誤認した
  - 🥕 鉛筆の線を小節線と誤検出した
  - 🥕 重い。2段だけの画像で約4分、メモリのピーク約6.8GB
  - 🥕 1段だけの画像や2値化した画像では失敗する

-> **拍子記号はAIに読ませるので、画像処理は小節線の位置だけに絞り、OpenCVで検出する。**

* AIが、検出の誤りを確認して補正指示を返す

* 補正指示にAIは座標を含めない
  * 指示の種類: 候補の削除、候補同士の結合
  * 分割・追加が必要な場合は、指摘として返す

* 出力: 補正後の小節の配列(段階1と同じ形)

#### 段階3: 楽譜読解(AI)

* 入力: ~~楽譜画像と、補正後の小節(番号付きの枠を描いた画像)~~ 2026-10-03 変更: 段ごとの画像と、補正後の小節(番号付きの枠を描いた段ごとの画像)
* AIが、`index` ごとに小節の内容を読む
  * 座標は出させない
* 出力を段階2の `bbox` と `index` で結合して、楽譜JSONを作る
* 例(結合後):

```
{
  "title": "DANCE MOVEMENTS",
  "composer": "PHILIP SPARKE",
  "part": "3rd Bb Clarinet",
  "tempo": {
    "mark": "I Ritmico",
    "bpm": 134,
    "beat_unit": "quarter"
  },
  "pages": [
    { "page": 1, "width": 2480, "height": 3508 }
  ],
  "measures": [
    {
      "measure": 1,
      "time_signature": "4/4",
      "beat_groups": null,
      "gp": false,
      "bbox": { "page": 1, "x": 120, "y": 340, "w": 410, "h": 90 }
    },
    {
      "measure": 2,
      "time_signature": "7/8",
      "beat_groups": [2, 2, 3],
      "gp": false,
      "bbox": { "page": 1, "x": 530, "y": 340, "w": 380, "h": 90 }
    }
  ]
}
```

#### フィールドの方針

* `time_signature`
  * 全小節に明示する(前の小節と同じ場合も省略しない)
* `beat_groups`
  * 楽譜から読み取れた場合のみ入れる。読めなければ `null`
  * 音から推定した結果はここに入れず、拍タイムライン側に持つ
* `gp`
  * GP(全休符 + "G.P." 表記)の小節を `true` にする
  * 通常の全休符の小節とは区別する
* `measure`
  * 段階2の `index` から採番する連番。楽譜に印刷された小節番号・練習番号とは別
* `bbox`
  * 段階1・2の結果を使う(段階3のAIは出さない)
  * 画像上の位置。小節のハイライトに使う
* 複数小節休符
  * 圧縮された1つの休符を、結合時に `measure` を展開して小節ごとの要素にする
  * 展開した要素は、同じ `bbox` を共有する
* テンポ
  * 曲頭の `tempo` のみ。曲中のテンポ変化・rit.・fermataは持たない

#### bboxの取り方

1. ✅️ 画像処理で小節線を検出し、AIは検出結果の補正と内容の読解だけを担当する
  - 👍️ 座標が正確に出る
  - 👍️ 検出の誤りをAIが補正できる
  - 🥕 小節線の検出処理を実装する必要がある
  - 🥕 AIの呼び出しが補正と読解の2回になる

2. 🗑️ AIに座標を出させる
  - 👍️ 実装が手軽
  - 🥕 座標がずれやすく、ハイライトが小節からはみ出す

-> **座標は画像処理、検出結果の補正と意味づけはAIと分担する。**

### 拍タイムラインの生成

1. ✅️ Librosaで拍候補の時刻を出し、AIが楽譜JSONと音声を見て「何小節目の何拍目か」のラベルを付ける
  - 👍️ 時刻の精度はLibrosaが機械的に担保する
  - 👍️ AIは強拍・GP・拍のまとまりの判断だけを担当する
  - 🥕 変拍子・GPでLibrosaの候補が外れた場合、AIが補正する必要がある

2. 🗑️ AIが音声と楽譜JSONを見て、拍ごとの秒数を直接返す
  - 👍️ 処理が単純
  - 🥕 長い曲で秒数がずれやすい
  - 🥕 音声入力を受けられるモデルに限られる

-> **時刻はLibrosa、ラベル付けと強拍の判断はAIと分担する。**


#### 出力(拍タイムライン)

* `{ measure, beat, time, strong }` の配列
* `beat` は後述の「まとまり」単位の打点

#### 指揮の打点の単位

1. ✅️ 拍のまとまり単位
  - 👍️ 7/8を2+2+3の3打で振れて、実際の指揮に近い
  - 🥕 まとまりの判断が必要(音から推定する)

2. 🗑️ 8分音符単位
  - 👍️ 判断不要
  - 🥕 7/8で7打になり、速いテンポで振れない

-> **まとまり単位で振る。まとまりを判断できない場合は、拍子の分子の数だけ振る(7/4なら7打)。**


#### 指揮のパターン

* 打点の数でパターンを固定する
  * 4打: □
  * 3打: △
  * 2打: 直線
  * 上記以外: 打点数分をそのまま振る
